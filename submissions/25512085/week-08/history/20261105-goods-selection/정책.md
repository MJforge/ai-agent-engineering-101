# Goods cohort 견적 선택 (2026-11-05)

- 기존 선택기가 정한 SKU·live grade·보증 cohort 안에서만 실제 `compute_unit_pricing_and_terms` 첫 견적을 비교한다. 카테고리 요청의 SKU 결정, 등급 선호, 정확 SKU 대체 금지, 식품 FEFO, 예약/committed 제외, 보증 고지는 유지한다.
- 최소 견적 기준 후보는 `(ask, hard_floor, cost, supplied_at, unit_id)` 순으로 결정한다.
- `B = min(ceil(기준 후보 cost × holding_cost_rate_per_day × holding_tie_horizon_hours / 24), ceil(최소 ask × holding_tie_max_fraction))`.
- `ask <= 최소 ask + B`인 후보 중 `(supplied_at, ask, hard_floor, unit_id)` 순으로 선택한다. 보관비 규칙은 원가의 **1%/일**이다. 기본 비교 기간 **24시간**, 견적 대비 상한 **2%**는 조정 가능한 명시적 정책 가정이다.
- 이는 **선택 허용폭**이며 견적 할인/가산이 아니다. 이미 `profit_floor`에 반영된 누적 보관비를 credit으로 다시 빼지 않는다. 재고 나이에 비례하여 허용폭을 무제한 늘리지 않는다. 기존 가격 공식·하한·clearance 정책은 변경하지 않는다.
- `cohort_selection_enabled=false`이면 기존 FIFO 선택으로 복귀한다. 새 수치 설정은 finite/nonnegative 숫자만 허용하며 bool·음수·NaN·무한대·문자열·null 및 계산 overflow는 FIFO로 안전하게 복귀한다. 누락된 설정은 위 기본값을 사용한다. 기간/비율 0은 허용한다.
- 누락/비정상/미래 supplied_at을 현재 snapshot 시각으로 해석하는 보정은 **cohort 내 선택 tie 정렬 전용**이다. 기존 FIFO의 `supplied_at or 0` 키와 카테고리 SKU 결정은 그대로 유지한다. 가격 계산에는 raw supplied_at 및 원래 unit을 전달하며, 원본 unit/state를 변경하지 않는다.
- 첫 요청에서 hub·시각·catalog·clearance snapshot을 공유하여 후보 비교와 표시/receipt의 최초 견적을 일치시킨다. 기존 직접 `select_best_unit`/`find_stock_unit` 호출은 선택 context를 생략하면 기존 동작을 유지한다.
- 추가 후보의 가격 계산에서 TypeError/ValueError/OverflowError가 발생하면 기존 선택으로 복귀한다. band 계산 전체도 같은 예외를 보호하며 각 설정의 `10**308` 정수 overflow를 포함한다.
- **한계:** 기존 malformed 입력의 가격/선택 개선은 범위 밖이다. 예컨대 음수 timestamp의 큰 누적 보관료는 그대로 보존하고, 문자열 timestamp를 숫자와 비교할 수 없는 기존 FIFO 한계나 원래 선택된 malformed unit의 가격 예외를 전역 보정하지 않는다. 허용폭 밖의 장기 고원가 재고 starvation 해소를 보장하지 않는다. 무제한 age credit이나 별도 청산 정책은 이번 변경에 포함하지 않는다. VM 배포·네트워크·실거래 검증은 수행하지 않는다.

검증: 신규 offline 테스트에서 수정 전 FIFO 실패를 보존했고, 수정 후 실제 Seller.execute, 8시간 분기, 등급/보증, FIFO off, 결정론적 순열, band 경계, lock 제외, 식품/정확 SKU, 설정/시각 이상, snapshot/receipt, 개별 가격 불변을 검사한다. 실행 원문은 새 `logs/goods-selection-*.log`에 보존한다. 기존 로그와 기록은 수정하지 않는다.

리뷰 후 추가 검증: raw `supplied_at=-1`인 B/C의 하한은 변경 전 `cash_policy.profit_floor(raw_unit, ...)`와 일치해야 한다(테스트 원가 100000 기준 B 24633334 / C 20938334). 수정 전 가격 회귀와 overflow 실패는 `goods-selection-review-before-*.log`에 별도 보존했다. 실제 comparable hub를 사용하는 A/B/C 복수 후보 cash-first-quote의 band 안/밖 선택·표시·receipt 및 등급별 8시간 분기 고정 가격도 검사한다.

최종 검증: 독립 리뷰가 지적한 가격 하한 변경과 큰 정수 overflow를 보완한 뒤, 메인이 HEAD 대비 diff를 확인하고 `.venv/Scripts/python.exe -B -m unittest discover -p test_*_offline.py`를 재실행했다. 신규 29개를 포함한 전체 **396개 테스트 통과**. 원문은 `logs/goods-selection-main-verification-20261105.log`에 보존했다. VM 배포 및 실거래 성과 검증은 미실행이다.
